## Requirement Evidence

- Append-only runtime event envelope support exists and is persisted through `RuntimeEventStore`.
- Workflow checkpoints are generated by Commander DAG lifecycle events and persisted through `WorkflowCheckpointStore`.
- Native database guards allow only the intended runtime/checkpoint table migrations and query shapes, including runtime event insert/replay/count/prune and checkpoint insert/latest/list/prune paths.
- Native database guards now also have explicit duplicate `(run_id, sequence)` runtime event and duplicate `(run_id, event_sequence)` checkpoint rejection coverage in `apps/desktop/src-tauri/src/database.rs`.
- Terminal runtime event streams now compact through `runtime.compacted` summary envelopes after `task.completed` / `task.failed`, preserving structural audit events while bounding raw stream text and hashing the full compacted payload.
- Checkpoint/event-log reconciliation exists in `workflow-checkpoint-reconciliation.ts`.
- DAG execution can resume from `WorkflowResumeState` without rerunning completed upstream steps.
- Commander DAG runtime accepts `resumeFromCheckpoint`, checks plan hash and event-log consistency, then passes resume state into the DAG executor.
- Restored durable approvals link to a checkpoint only when checkpoint/event evidence is consistent.
- Restored approval approval-success paths can continue the original Commander DAG with `resumeFromCheckpoint`.
- Approval-success resume advances the single waiting approval step to completed and writes its execution result into checkpoint context before restarting the DAG, avoiding a second execution of the approved write step.
- Computer Use step outputs stored in SharedContext are sanitized before verifier handoff; raw `data:image` payloads and typed text are not propagated through `computerResult`.
- Commander DAG step outputs now write `ArtifactEnvelope` metadata into `SharedTaskContext` through `writeStepArtifactOutput`, preserving legacy payload reads while letting workflow checkpoints persist producer step, agent, tool name, schema version, content hash, and sensitivity.
- Commander DAG step failures now emit explicit durable `step.failed` runtime events, so replay/checkpoint consumers can distinguish failed step lifecycle transitions from task-level failure logs.
- Durable approval records now carry optional `runId` through `approval_records` persistence so restored approvals can re-link to the latest checkpoint for the same run, while legacy records without `runId` still load and validate.
- Existing SQLite installs now get an `approval_records.run_id` additive migration with a duplicate-column-tolerant migration marker; Rust IPC guards only allow the exact `ALTER TABLE approval_records ADD COLUMN run_id TEXT` shape and continue rejecting unrelated `ALTER TABLE` statements.
- Workflow checkpoint construction now preserves `ArtifactEnvelope` entries passed through `contextSnapshot`, so persisted checkpoints keep durable artifact provenance instead of dropping restored envelopes.
- Workflow resume hydration now preserves envelope metadata from checkpoint snapshots instead of downgrading all restored artifacts to raw payloads.
- Product workflow evidence gating now tracks the remaining packaged restart-resume proof as `agent-runtime-durability-restart-resume`.
- Source-level runtime event compaction coverage now includes `runtime-event-store.test.ts` and the `app-runtime` terminal-compaction wiring check.
- Runtime event compaction now has explicit test coverage that terminal pruning preserves task, step, and permission lifecycle events while replacing streaming chunks/partials with a `runtime.compacted` summary.
- Checkpoint reconciliation and restored-approval linking now accept permission evidence from either `permission.requested.request.id` or flat `permission.requested.approvalId` payloads.
- Commander DAG resume now rebuilds from the durable event log when checkpoint step state conflicts, and the rebuilt resume path is surfaced in emitted logs as `workflow.resume.rebuilt`.
- Completed Commander DAG snapshots now persist structured `durableResume` metadata with run id, resume source, checkpoint/latest event sequence, skipped/retry step ids, approval ids, and rebuild status; task history sanitization preserves this metadata.
- Completed task history also preserves structured `verificationResult` records so verifier outcomes survive restart/reload alongside the existing summary text.
- P1 WorkspaceRuntime now has a shared core contract plus focused route helpers for Code, Shell, and Git tools, with `LocalReadOnlyWorkspace` write attempts failing closed and desktop `DisposableCopyWorkspace` / `WindowsSandboxWorkspace` adapters wrapping the existing temporary workspace sandbox read/list/execute/snapshot/diff/finalize commands. Full Commander DAG execution through this boundary remains a follow-up integration item.
- P1 read/preview sub-agent delegation now has an explicit `getDelegableSubAgentsForPlanning()` surface and `delegation-policy.ts` guardrails so confirmed-write tools remain parent-coordinated while sub-agent planning surfaces filter write capabilities.
- P1 recovery reports now keep `handoff` failures, stuck signals, and Commander guidance aligned across core snapshots, desktop task history/session logs, and UI recovery details.
- Legacy task history recovery reports without stuck metadata now normalize to empty `stuckSignals` / `commanderGuidance` arrays, so older saved task snapshots remain render-safe after the P1 schema expansion.
- Workflow resume reconciliation now passes checkpoint `ArtifactEnvelope` entries through to executor hydration, preserving artifact metadata while keeping legacy payload reads available through `SharedTaskContext`.
- Checkpoint plan hashes now include execution-significant fields such as title, input/output contracts, capability/dependency layout, permission level, context keys, output keys, and parallelism, so incompatible DAG mutations do not appear resume-compatible.
- Restored approvals with legacy records that lack `runId` no longer fall back to the latest task checkpoint, preventing ambiguous records from claiming run-scoped recovery.
- Restored approval checkpoint linking now replays runtime events through the checkpoint event sequence instead of relying on the default 10,000-event replay cap.
- Commander DAG durable persistence now flushes event append and checkpoint save operations before the task returns, preventing checkpoint saves from outrunning accepted runtime events.
- Progress ledgers are now attached to recovery reports during Commander DAG recovery and preserved through desktop task history/session log sanitization, including explicit JSONL session snapshot coverage.
- Read-only project inspection and code review verification helpers can now route shell execution through `WorkspaceRuntime.execute(..., permissionLevel: "read")` when a runtime is provided, and `createFileScanTaskRuntime` passes the optional runtime through to those flows. Desktop `createJavisRuntime` now wires a live `LocalReadOnlyWorkspace` backed by the existing `run_read_only_command` IPC path, with a lazy workspace-root provider so workspace path changes are reflected. Git stage/commit execution also has a Commander DAG path that runs approved operations through a write-capable `WorkspaceRuntime` while keeping local read-only workspaces fail-closed.
